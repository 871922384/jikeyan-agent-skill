# 投稿前检查

对每项记录“已核实 / 待核实 / 不适用”、依据和确认人。需要用户提供现行期刊要求与可用材料；MCP 不接收附件，科学及伦理决定由研究团队负责。

## 逐项操作

### 期刊要求
怎么核对：逐项对照期刊乙当前作者指南的文章类型、格式、字数、文件及投稿系统要求。需要用户提供什么：目标期刊和当前指南、稿件版本与拟投类型。常见坑：引用过期指南或把不同文章类型的要求混用。

### 伦理与注册
怎么核对：确认是否适用，将声明与批准文件及注册记录核对。需要用户提供什么：适用性判断、批准与注册凭据及声明。常见坑：由 Agent 作伦理合规结论，或写入患者信息。

### 作者与贡献
怎么核对：核对顺序、贡献及每位作者对最终稿的同意。需要用户提供什么：作者清单、贡献和确认记录。常见坑：只收到代表的口头确认就假设全体同意。

### 利益冲突
怎么核对：逐位作者对照期刊表格核对申报与签署状态。需要用户提供什么：各作者声明、期刊表格。常见坑：缺失声明被当作无利益冲突。

### 数据可用性
怎么核对：核对声明、访问条件、实际存放和许可一致。需要用户提供什么：拟用声明及管理安排。常见坑：承诺无法兑现的开放访问；不上传受限数据。

### 参考文献
怎么核对：对照正文与文末条目、格式及引用对应关系。需要用户提供什么：稿件和文献清单、独立核验结果。常见坑：格式正确不等于文献真实；可用 `verify_references` 做元数据一致性核验（见工具说明），它不能证明引用内容正确；撞题检索见 [选题撞题](topic-collision.md)。

### 图表
怎么核对：核对编号、正文引用、图注、分辨率及授权。需要用户提供什么：最终图表、稿件和授权资料。常见坑：图表版本与正文不一致，或漏核转载许可。

### 致谢与基金
怎么核对：逐项核对支持来源、编号、致谢对象及许可。需要用户提供什么：团队确认的支持清单和许可。常见坑：未经同意列入致谢或复制旧编号。

### Cover letter
怎么核对：对照期刊、题目、类型、投稿声明及稿件内容；作者审核全部声明。需要用户提供什么：信件草稿、期刊要求和作者确认。常见坑：沿用其他期刊名称或声称未核实的原创性。

### 查重
怎么核对：由用户用有权限的工具取得报告，逐处解释重合及引用。需要用户提供什么：报告、稿件及其处理意见。常见坑：以单一比例自动认定通过；Agent 不代替研究者判断。

## 常见坑
缺材料的项目必须标待核实；清单是组织工作的工具，不是自动投稿资格认证。
