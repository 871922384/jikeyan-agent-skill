# 每日复盘

## 操作步骤
1. 确认用户时区，用 `get_today` 的 tz 获取逾期、临近截止、到期复查和最近进展；同时用 `list_projects` 查看可见课题。今天清单不含没有 `next_check_at` 的等待项，重要课题需用 `get_project` 补查未完成等待项和节点。
2. 从 Agent 自己的持久存储按账号和服务隔离读取上次游标；没有游标时不带 cursor 调用 `get_changes`，保存返回的 `next_cursor` 为基线。首次只从现在开始，不覆盖之前历史。
3. 已有游标时逐页读取：先处理和记录本页，再持久化该页 `next_cursor`，`has_more` 为 true 时以它继续。变更只给 `changed_fields` 字段名，必要时按 `project_id` 重读现状；`by_you` 表示是否当前账号本人，不能据此猜出具体他人。
4. 多课题先排已逾期且影响外部截止的事项，再排今日截止和到期等待项，再按截止时间、依赖阻塞程度排序；同级按用户优先级和稳定的课题名称排序。标出需要用户决策和可并行事项，不用更新时间代替截止时间。
5. 对照 [判断标准](thresholds.md) 各行判定阶段及等待风险，标明事实、推断和覆盖范围。建议下一步须能执行，缺信息则明确待确认。

## 游标恢复
保存失败时保留旧的已持久化游标，停止继续推进并提示用户；恢复后从旧游标重读，按变更对象、版本和时间去重，避免漏项。处理本页失败同理，不保存该页新游标。若返回 `invalid_cursor`，记录历史覆盖中断，按错误提示不带 cursor 重新建立基线；用 `list_projects` 和重点 `get_project` 重建当前状态，但不能声称补回中断期间全部变更。持久存储不可用时告知用户，下次不能可靠续读。

## 示例：2026-11-06 简报
假设当前时区为 Asia/Shanghai，用户已建立基线且读完全部变更页。

### 今天必须处理
- 课题甲：修回截止 2026-11-06，尚有逐条回复待核实；先核对稿件位置并请作者确认后提交。
- 课题乙：等待合作者丙确认的复查日期为 2026-11-06；先核实是否已有回复，再起草提醒。
- 课题丁：材料节点 2026-11-07 截止，依赖课题组确认；今天请用户决定优先顺序。

### 正在拖
- 课题甲：当前阶段停留已超草案线；阶段时间有记录，建议确认阻塞原因及修回计划。
- 课题乙：等待项最后更新时间较早，但最后回复日期未知；无法确认是否超跟进线，先问用户。

### 别人改了什么
- 课题甲：非本人账号改了课题阶段；重读后当前为修回阶段，变更摘要不显示原值或具体修改人。
- 课题丁：非本人账号改了节点截止字段；重读显示现截止 2026-11-07，原截止时间未知。

## 常见坑
首次游标不是历史导出；最近进展不是全部历史；本人账号操作也可能来自其他客户端，不能把非本人账号等同某个特定成员。没有持久化成功时不要假装下次能续读。
