# 首次使用与建立课题

## 第一次对话先开场，再建课题

用户第一次跟你聊时，先按 SKILL.md“第一次对话”做开场：静默调用
`get_schema` → `get_today` → `list_projects`，用 `schema.welcome`
（缺失时用 `../jikeyan-agent/references/welcome.md` 兜底）按用户语言说开场白、
列能力、给 3 条建议，等用户挑。用户应答后，再按下面的“首次使用”确认课题。
开场是后台摸底，不要念工具名；不提密钥（用户问起再答）。

## 首次使用
1. 调用 `get_schema`，读取用户课题类型对应的阶段、枚举和限制，再调用 `list_projects` 获取可见课题。向用户展示名称与当前阶段，请用户确认要管理哪些课题、当前阶段是否准确；不把列表当作账号外全部课题。
2. 无游标时不带 cursor 调 `get_changes` 建立基线，在 Agent 持久存储中按账号和服务保存 `next_cursor`；说明基线之前的变化不会回放，保存失败则告知不能可靠续读。需要现状时对确认的课题调用 `get_project`。
3. 根据用户说出的目标、截止和依赖提出初始节点草案，列清标题、种类、日期、时区和依据；日期未知就标待确认。获得用户对具体节点的同意前不擅自创建。不要指派成员或上传附件。

## 将用户口述转成课题
先复述课题名称、目标、类型和阶段，向用户确认；对照 schema 选择模板和阶段，不把研究数据或患者姓名、住院号、诊断或随访原文写入。为外部来源生成稳定、不含敏感信息的 `external_ref`，记在本地，后续重复导入原样使用；先用 `list_projects` 按该引用查询，另向用户确认是否与现有课题重复。已归档课题不参与服务端去重。

用户同意创建后，`create_project` 传 title、`template_id`、objective、stage 和 `external_ref`，先用 `dry_run` 预演，核对回执后正式写；若命中已有课题，核对是否就是目标，不能假称新建。取正式响应的课题 ID，再对每个用户确认的节点用 `upsert_node` 传 `project_id`、kind、title、`due_at` 及需要的 tz；逐项先预演再写并重读。课题创建与节点写入是独立操作，节点失败要如实报告并可单独恢复。限定范围 Key 不能新建，见 [写入规范](write-discipline.md)。

## 示例：课题甲
用户说：“建立课题甲，目标是整理研究方案，采用论文流程，先准备初稿，2026-11-20 前完成提纲。”先核对 schema，复述并确认论文模板及写作阶段；拟用稳定引用 `example:project-a`，确认尚无对应课题。用户确认后，预演并执行 `create_project`：title 为课题甲、template_id 为 paper、objective 为整理研究方案、stage 为 drafting、external_ref 为该引用。返回正式课题 ID 后，提议“完成提纲”截止节点，日期为 2026-11-20；仅用户确认后使用 `upsert_node`，kind 为 deadline，传对应 ID、title、`due_at` 和 tz，先预演、再写入并复读。

## 常见坑
无 cursor 的首次调用不是导出历史；外部引用应稳定，不要每次随机生成；预演 ID 不可作为已创建课题使用；默认阶段不能替代用户确认。
